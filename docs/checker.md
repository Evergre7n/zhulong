# 检查器范围

检查器是只读的 Markdown lint 工具。它检查记录章节、查询登记、台账字段、部分日期、三问作答，以及部分证据关系词法规则。对历史版本按声明保留兼容性；版本声明和目录日期并不证明真实创建时间。

## 交付前如何使用

先检查关键结论是否由正确对象、版本、单位和时点的原文支持，再运行 `--strict`。逐条处置 WARN；必要时用 `--fail-on-warn`。发现误报时保留原判断和人工复核理由，不靠移编号、拆句或降版本来隐藏。

## 已知局限

- 不是语义验证器。对否定句、复合失败状态、跨句推导和例外理由，可能误报或漏报；“读取失败，仍未取得正文”这类文字需要人工识别，不能仅凭 PASS 承重。
- 不能证明某页面被实际读取、全文被保存、网页或日志未伪造、来源独立或作者真实。哈希只能核对给定字节。
- 不证明搜索覆盖完整，也不证明“全网最高/最低/不存在”。
- 证据编号冲突提示只覆盖部分编号形状，不会自动消歧。相同数字不证明同一来源。
- 价格时效提示采用固定30天；用户更短的决策窗口、税费、SKU、库存和可购买条件必须人工核对。
- 历史规则包含关键词识别，正文碰巧出现关键字不保证该要求真正完成。

## 输入与依赖

输入必须为包含 UTF-8 Markdown 的目录。列目录、读文件或解码失败会报告 FAIL；指定不存在路径、文件路径及无默认研究目录会返回使用错误。一次运行重新读取登记规则，避免沿用上次调用的缓存。

登记簿支持以 `#` 为首列、含 `识别词` 的 S-001 来源规则表，以及以 `#` 为首列、含 `状态` 的 V-001 事实表。空表或明确空文件表示零条规则，并在输出显示数量；缺失、读失败、非空但无法识别的格式、重复规则编号或必要字段为空会报 FAIL。没有内置的普遍来源黑名单。

`--no-registry` 显式关闭此部分并产生 WARN；这既跳过来源失效规则，也跳过价格登记检查。不能将该次输出宣传成已检查登记簿。

登记簿中的活动表格须有开头竖线和合法 Markdown 分隔行；代码块中的表格只作示例，不载入规则。正文中以 S-/V- 编号开头的表格行若未被合法表格完整解析，会报告 FAIL。

`--self-check` 单独运行内置合成正反示例，不能与 `--json`、`--strict`、`--fail-on-warn`、`--registry` 或 `--no-registry` 组合。组合使用返回用法错误（退出码 2），不会把自测结果混同于用户研究记录的检查结果。

## 召回缺失的表达

v1.6 允许诚实披露未做事前登记。当前检查器识别以下整行，并产生 WARN 提醒覆盖未获证明：

`召回探针：未预登记；原因：本题没有独立种子；相对召回：不可计算`

原因应替换为实际情况。该行不证明原因合理，也不是免除候选搜索的许可；其他自然表达仍须人工处置可能的格式提示。
