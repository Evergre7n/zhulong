# 评估说明

烛龙目前是可复核的研究流程与记录规范。现有开发试验不足以证明总体准确率、速度或成本优势。检查器测试与研究方法对照是两类证据，不能互相代替。

## 发布前同题对照：2026-10-28

题目：**全网范围内 TP4 DGX Spark 部署 deepseek-v4.1-flash-1017 最快的 C1 Prose 和 Code 是多少？**

每组比较直接联网研究与额外读取冻结 v1.6 协议的研究，各臂一次、独立会话。同组题目、工具条件、40次可见联网子动作和1500秒上限一致；失败和批量请求子项计入，搜索结果条数不计作额外动作。协议臂没有运行结构检查器，因此不是整套工具流程的试验。

| 运行环境 | 直接研究 | 协议文本 |
|---|---|---|
| Codex，请求 gpt-6.1-terra / xhigh | 40次动作；收据313.342秒 | 40次动作；收据221秒 |
| MiniMax Code 0.7.0，原生返回 MiniMax-M3.1-Flash / thinking | 15次动作；389.967秒 | 27次动作；551.228秒 |

MiniMax 两臂均为 standard、64原生步骤上限；这是额外的执行约束，不等于联网次数硬限。动作由可见请求复计，隐藏重试与服务端请求数未知。耗时包含运行环境开销，不能由单次差值推定稳定的速度收益。Codex 的服务端模型身份、token和费用无独立认证；MiniMax原生返回型号也不是第三方认证。

## 实际观察

- Codex 协议臂发现了直接研究臂未列的原生权重候选，并明确留下一个更高 Prose 线索；直接研究臂看到了该线索却未在答案处理。但两臂均漏掉了另一份较高的原生 Prose 记录，也没有逐条核清计时分母。
- MiniMax 两臂都找到上述较高 Prose 记录。协议臂留下较完整的研究档案，却没有改善 Code 最高候选的回答；直接研究臂的可见正文含更高的复制代码结果，最终答案仍未披露。文档齐全不能抵消漏项或比较错误。
- MiniMax 直接研究臂把搜索返回条数算作动作，错误地认为已超预算，因而提前停手。协议臂自报26次，日志复计27次；二者都在40次可见动作上限内。预算自报需要与实际调用核对。
- 原题中的“最快”不能靠混合不同权重、复制代码提示、普通代码提示、直接探针和不同计时区间来回答。谨慎的未知声明有价值，但不自动证明搜索充分或核心答案正确。

具体记录可从作者资料核查：[knapcio 测量历史](https://github.com/knapcio/DeepSeek-V4.1-Flash-4x-DGX-Spark-TP4/blob/main/docs/history.md)、[NVIDIA论坛部署报告](https://forums.developer.nvidia.com/t/new-deepseek-4-1-flash-recipe/384438?page=2)、[Bertholomus TensorFold结果](https://github.com/bertholomus/deepseek-v4.1-tensorfold-tp4-4xgb10)、[Keenni直接探针说明](https://github.com/Keenni/DeepSeek-V4.1-Flash-1017-UNCENSORED-DGX-Sparks/blob/main/docs/tp4-tensorfold-zig.md)。这些是部署者自报，不是本项目的硬件复测或统一排行榜。

## 记录质量与局限

Codex 直接研究臂的8份原始网页回包中有2份在保存时截断；协议臂8份均能解析。独立审查员的部分新网页返回也因保存错误遗失，后来只补核关键事实。因此不把这组当作完整轨迹的合格基准集。

MiniMax 首次尝试的直接研究臂被用户级技能自动发现污染，读取了烛龙；在最终答卷产生前终止并保留失败记录，未计入有效对照。随后关闭本次调用的外部技能发现，保持原顺序重新运行一组。有效两臂的原生事件可解析，源工件均在清理会话前归档；没有观察到读取其他会话或本地模型。共享用户配置、服务端状态和完整模型输入仍不是OS级隔离或第三方可认证状态。

MiniMax报告用量如下，字段照原生结果保留；其中协议臂明确标记不完整，不能换算账单或当完整总耗用：

每组仅一个题目、每臂一次，来源发现路径不同；主研究者非盲态，独立审查也无法保证盲态。没有固定完备的世界纪录金标准，不把十项事实/证据/覆盖检查求和成准确率，不选赢家，也不把后验补查回填为被试当时已知。

原始网页、会话日志及包含本机路径的运行档案未全量公开。此页提供有限观察与主要原始来源，不是能够逐事件重放的公开数据集。

## 发行决定
