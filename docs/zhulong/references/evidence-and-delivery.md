# 证据与交付格式 · v1.6

单文件和多文件等价；短题优先单文件。文件名不是完成标准，正文必须有证据与作答。

## 最小研究记录

1. `# 立案卡`：原句、对象×问题×决策、硬约束、时间窗/时区、语言面、读法、关键假设及失效影响；写“烛龙预设 P-00x · YYYY-MM-DD · 协议 v1.6”、L1/L2/L3 和总预算。
2. `## 查询词登记`：实际查询原文/直接来源读取路径/实验命令，每项写日期和结果；失败步骤也登记。标题或“已查”不能代替记录。
3. `# 覆盖表`：命题/必要证据面、状态、已做动作、缺口及停止理由。允许“已关”“N/A+理由”“未关闭，已传待开”；已解决判定但全域未饱和应明确说明。
4. `# 证据台账`：至少一条有效证据。若确实未取得任何证据，只能交付失败记录/未知，不能提交有据裁定；体检失败如实报告。
5. `# 未知桶`、`# 碰壁记录`、`# 待开清单`：可以各一段；没有事项写清原因，不能留空标题。未知项写改变结论所需的证据、已试路径、下一次动作或外部依赖。
6. `# 结论`：回答原问题，区分已证实、不符、矛盾、未知；关键结论显式回指证据编号，注明成立窗口。
7. `# 自查` / `## 交账前三问`：用 1/2/3 分项回答：①硬约束和窗口是否逐项兑现；②结论引用哪些证据、关系计算是否一致；③补查是否传到，尚存哪些缺口。本轮没有补查也说明“无补查”及相关待开情况。

## 台账字段

| 字段 | 内容 |
|---|---|
| ID / claim | 唯一编号 E01…，断言与适用范围 |
| URL / 对象 | 完整 URL；本机实验则写命令、原始输出文件与局部效力边界 |
| 原文短引句 | 足以复核主语、限定词与单位；长引文遵守来源使用限制 |
| 日期 | 区分发布/生效/观察日期；采集时点使用 ISO 8601 UTC，并记用户相关时区。未知发布日期不伪造 |
| 读深 | 全文 / 落地 / 摘要；模型改写的摘要不冒充全文 |
| 来源类型 | 第一方 / 当事方 / 二手 / 聚合 / 用户口径 / 本机实验 / 未知 |
| 信息状态 | 独立双源证实 / 单源 / 有矛盾 / 无法判断；“第一方”不自动等于事实已获证实 |
| 限定/标记 | 非官方镜像、子体系、版本、承重禁用或带依据的例外；有需要才加专门列 |

全文读取应保留原始抽取文本或可重放路径；仅有网页标题和 200 状态不够。完整内容无法归档时保留短引句、URL、观察时间和读取限制，不声称已有不可变快照。

## 现行性与更新

条款、价格、版本、状态先看第一方当前内容和生效日；涉及“何时改变”或来源冲突时再取历史快照，不把每次现状核查都扩成历史考古。无法绕过访问限制时保留未知。
影响结论的易变事实登记到项目自己的登记簿；仓库提供 `docs/zhulong/volatile-facts-registry.md` 空模板，检查器可用 `--registry` 指定路径；历史事实与新观察分开。修订保留原文，加作废/替代标记及证据链；修订后的结论重新验收。

## 体检边界

在本仓库根目录运行 `python scripts/zhulong/dossier_check.py <目录> --strict`。只有协议文本而没有运行环境时，逐项人工自查，并标明结构检查未运行。固定回归用例位于 `tests/test_zhulong_dossier_check.py`；`--self-check` 运行随包的合成正反对照；它们不是内容质量分。
机械检查可以验证非空、字段、日期与部分关系，但不能证明来源真伪、搜索全覆盖或推理正确。不得靠同义改写、拆句、移编号或自报旧版本来绕检查；误报说明实际命题与出处，保留处理理由。
