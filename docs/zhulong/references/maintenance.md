# 维护与验证 · v1.6

## 修改规范

常驻核心保留普遍且影响决策的步骤；领域规则放在对应预设。新增条款先看能否合并或替代旧条款。
新硬约束应有两个独立案例，或一个案例加机制说明，并记录适用范围、反例与执行成本。候选与正式规则分开；没有证据支持的候选不随版本发布。
修改正本后运行测试、生成可携技能并检查同步。历史研究按其声明版本审计；修订旧事实时保留原结论和修订依据。版本声明不能作为真实性证明。

## 质量复核

按风险抽样，回原始来源核对关键判断，记录成立、不成立或无法复核。优先检查影响决策的数字、来源身份、单位、版本和时点。
评估协议效果时，先冻结题目、评判标准、模型、工具和预算，再执行对照。报告事实错误、关键遗漏、证据支持、实际时长及可观察用量；拿不到 token 或账单时明确未知。
用于修改规则的样本属于开发样本，不能再作为独立留出；单次或小样本对照不证明总体优劣。

## 当前验证边界

本版本包含研究流程、记录格式与可选结构检查器。开发阶段进行了离线和有限联网试验，但不足以证明开放网络上的总体准确率、效率或成本优势。
结构测试与示例只能证明所测格式、输入处理和部分启发式检查的行为。检查器不能认证网页来源、实际阅读、事实真实性、搜索完备性或自然语言中的全部推导关系。
发布前的检验记录见仓库根目录 CHANGELOG；后续公开评估须给出方法、样本、预算、偏差和可复查材料。
